Data and export

Everything you need to work with the archive on your own: where the data came from, how to cite it, the whole dataset as a download, what's in an export, and the read-only API.

Provenance

SourceInternet Archive item WPA-L-1993-2021-Complete-Uncompresse, public-domain mark: 341 monthly LISTSERV logs, January 1993 to May 2021, each checked against the item's published MD5.

ProcessingThe logs are split into messages, every email address is removed, attachments are dropped, threads are rebuilt, and each poster's addresses and name spellings are grouped into one person. The code that does this, and the decision files that correct it, are versioned along with the reader.

How to cite the archive

WPA-L Archive Reader. Built from WPA-L Archive 1993–2021 Complete Uncompressed, Internet Archive, 2021. Build {{ build }}. {{ url_for('home', _external=True) }}

Every message page has MLA 9 and APA 7 citations for that message. To cite a saved corpus, use its URL and the build date shown on it.

{{ ic('ic-data', 'ic-sm ic-quiet') }} Export fields

FieldMeaning
message_idStable 12-hex id; the permalink is /m/{id}. It does not change between builds.
thread_idThe id of the thread's first message; the thread page is /t/{id}.
poster_idThe person id (addresses and name variants grouped). In a pseudonymized export, a pseudonym.
poster_nameThe name as posted on this message. In a pseudonymized export, the same pseudonym as poster_id.
date_utc, year, monthThe Date header in UTC; year and month as filed (the log's month when the header disagrees with it).
genreQuery, discussion, debate, CFP, job ad, announcement, tribute, list business, or other; see the Genres page for how labels are made and how accurate they are.
subject, bodyAs posted, with addresses removed.
body_own_wordsThe body without quoted text (> lines, forwarded and "Original Message" blocks) or the signature block. Heuristic; see the methodology.
permalinkThe message's URL in this reader.

Exports and saved corpora top out at {{ "{:,}".format(export_max) }} messages each, and they never include withdrawn messages. Pseudonyms stay the same within one corpus or one exact search, so downloading again gives you the same ones, but they change from one corpus to the next. Pseudonymizing only covers the name and id fields, though. Names inside the message text (signatures, "X wrote:" lines) are still there.

API

The API is read-only JSON under /api/v1/, limited to {{ api_rate }} requests a minute per client, with {{ api_page }} results a page. Withdrawn messages and people are left out here too.

GET /api/v1/messages/{id}One message, with its citations.
GET /api/v1/threads/{id}A thread and its messages.
GET /api/v1/search?q=&from=&start=&end=&fresh=1&page=The search page's filters; fresh=1 matches own words only. Includes a next link.
GET /api/v1/corpus/{id}A saved corpus: its query, build, frozen ids, and a page of messages.
GET /api/v1/posters/{id}A person with a public page: names as posted, activity, affiliations.
